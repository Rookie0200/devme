# The legacy Q&A and meeting product is removed, not paused

This repository began as a Q&A dashboard over an indexed codebase, with meeting transcription attached and a roles-and-invites workstream underway. It is now a spec-adherence pull request reviewer. Both products lived in the tree at once for the duration of the pivot; the second is now deleted outright rather than left dormant behind a feature flag or on a branch.

The cost of leaving it was not hypothetical. Sixty-nine of the repository's seventy-two standing lint errors were in dead code, and that documented baseline is what let two genuine build breakages — a missing `"use client"` directive and a missing default export — survive undetected until a build was attempted for an unrelated reason. A baseline that has to be remembered in order to be interpreted is not a baseline; it is a broken signal with a note attached. The env schema required a transcription credential the code no longer called, so the build refused to run without a key for a dead service. The repository loader fell back to a stored personal access token when its caller passed none, which is the exact credential model `docs/adr/0001` exists to forbid. The public landing page advertised meeting transcription, quoted invented testimonials, and listed pricing tiers that were never offered.

What went: the meeting surface and its transcription and upload clients; the Q&A dashboard, its streaming answer route, and its commit-summarization module; the roles and invites workstream that `docs/adr/0001` had already cancelled; the legacy tRPC router; the `Project`, `UserToProject`, `Meeting`, `MeetingIssue`, `Question`, and `Commits` models with the `MeetingStatus` enum, `User.credits`, and the legacy ownership column on Codebase Index storage; the marketing site; and the stale project guide and infrastructure proposal.

What stayed: everything the reviewer needs. The AI integration and repository-loading modules survive because Codebase Index construction calls them — the loader narrowed rather than deleted, and its ambient-token fallback removed. The Auth.js identity models are untouched.

## Consequences

- **The reviewer has no user interface.** Every authenticated page belonged to the old product, so signing in now lands on a placeholder that states the reviewer runs from a GitHub App installation. This is deliberate: the Installation and Provider Key surfaces are the next piece of work and should arrive in a diff that can be read on its own, not buried inside a thousand-line deletion. Until then, a Provider Key can only be supplied by the seeding script.
- **The test suite could not verify any of this.** It enters at one seam, the webhook handler, and drives the in-memory store and the fake Codebase Index — so it never reaches the persistence-backed implementations the schema change modified. All twenty tests passed throughout, and would have passed had the work been catastrophic. The gate was lint reaching zero errors, a passing build, and one live Review Run against a real pull request. Anyone repeating an exercise like this should assume a green suite means nothing and arrange different evidence.
- **The removed code is recoverable from history**, and some of it is worth recovering. The streaming answer route in particular was competent work — a raw token stream with matched files returned out-of-band in a header rather than muddled into the body. It was removed because the reviewer has no answer surface and no plan for one, not because it was bad.
- **The glossary is now a description rather than an aspiration.** `CONTEXT.md` listed Project, Member/Role, and Meeting under retired terms while all three still existed in the schema. They no longer do.
- **This decision is not reopened by wanting a Q&A feature later.** If the reviewer grows one, it should be designed against Installation and Repository, the ownership model the product actually has, rather than revived against a retired one.
